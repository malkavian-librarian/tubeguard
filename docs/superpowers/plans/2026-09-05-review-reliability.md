# Independent reliability review

Reviewed the draft and existing time-tracker.js, storage.js, blocker.js, service-worker.js and stats.js. No implementation changes. Recommended disposition: revise before execution.

1. **HIGH — Evidence snapshots are not implementable with the stated schema.** Runs refer to evidence versions but `videos/videoId` overwrites the only stored evidence. A revisit during a run can make a version unavailable or change inputs between retries. Add immutable `video-evidence/evidenceVersion` records (including owner provenance), with videos holding the latest pointer; atomically snapshot selected version and coverage before requesting. Alternatively persist all immutable request parts at selection time. Specify a unique coverage record per watch-chunk, policy revision and reset epoch, rather than the undefined “unique coverage key.” Test a changed transcript during a two-part run and a crash after the first part.

2. **HIGH — Configuration cancellation has an unstated cross-storage race.** Rereading enabled/generation before an asynchronous sync write does not prevent disable/delete from committing between that read and write. Serialize config transitions, delete, manual block mutations and outbox application in the same worker mutation queue; define transition acknowledgement as the linearization boundary. Keep authoritative policy/generation in IDB with decisions, and store only key material separately in local storage through a staged/recoverable config operation. Test disable while sync.set is pending, worker death between local-key and IDB config commits, and delete between final generation check and sync write. Explicitly define whether already-applied automatic blocks survive disable (recommended: yes).

3. **HIGH — Capture epoch and replay acceptance are underspecified.** Assigning revision at acceptance credits delayed/retried old viewing to newly saved priorities; resetting by acceptedAt has the same defect. Add worker-issued capture epoch/config generation to session handshake and checkpoints, persist session identity/sequence progress, and accept duplicates by key before monotonic-order rejection. Flush/rotate epochs on settings changes, exclude old-epoch delayed checkpoints from current policy, and clip/exclude intervals crossing channel reset boundaries. Define stable logical session identity across worker restarts versus a newly loaded document. Test delayed checkpoints after priorities change/unblock and out-of-order retry acknowledgements.

4. **HIGH — Channel identity feasibility is a second release gate.** The draft requires canonical UC IDs exclusively from owner hyperlinks, yet does not require T1 to prove that an active owner exposes such a hyperlink alongside handles. This can produce successful transcripts but zero automatic blocks. Require T1 to demonstrate canonical UC resolution and matching aliases on representative live pages under the permitted provenance rule; otherwise stop automatic-block completion claims and explicitly amend the adapter strategy after review. Unblock must remove all aliases belonging to that automatic decision and resolve handle UI requests to the canonical reset watermark; retain IDs independently blocked manually. Test unblock by handle then restart and revisit.

5. **HIGH — Quota/backlog behavior can starve processing forever.** Daily maxRequestsPerRun does not define a persistent daily budget shared across run-now/retries, reset boundaries, or exhausted-run rollover. Define a durable budget ledger by 24-hour window, a continuation alarm at window renewal, and deterministic terminal/deferred outcomes. Unavailable/invalid evidence must leave the runnable queue until evidence changes; one such oldest video must not block all later videos. Large transcripts producing more than 50 parts need part-level progress across budget windows with the same snapshot. Test a permanently unavailable oldest video, a 60-part video and repeated run-now.

6. **MEDIUM — Five-second legacy rows change existing statistics.** Existing stats.js counts session rows as sessions/video views and loads the entire sessions store with getAll. One row per checkpoint turns a 30-minute view into 360 views and causes rapidly growing full-store reads. Aggregate legacy stats once per logical session/date using an atomic increment guarded by chunk deduplication, or change readers to distinct session IDs and bounded queries. Preserve positive partial AI history independently of existing two-second legacy filtering. Test that 360 checkpoints produce one logical session/view, accurate duration, and two correct date totals across midnight.

7. **MEDIUM — Storage pressure policy cannot preserve endless small data.** The 250 MiB rule stops only large evidence, while chunks, exact input snapshots and audit continue indefinitely; eventual quota exhaustion can prevent logging the failure itself. Count all feature stores, reserve a small fixed status budget, define a storage-full paused-capture state before the hard limit and display it on inspection. All failed transactions must leave prior history intact and must not advance acknowledged coverage/accounting. Clarify that retention is until deletion or capacity exhaustion; no guarantee of unlimited retention. Test quota failure at checkpoint, snapshot and decision transactions.

8. **MEDIUM — Worker continuation and interval arbitration need concrete contracts.** T3 assigns cross-window arbitration to the worker without fields for clipped active subintervals or ownership in T2; activeMs alone cannot allocate partial overlap to media ranges. Add explicit active wall intervals mapped to media intervals and transactional overlap arbitration in T2, or defer cross-window deduplication with an explicit product rule. For MV3 jobs, require each step to persist its next wakeup before yielding; specify recovery alarm when a lease expires, not merely “resume after expiry.” Test termination after cursor commit without subsequent calls and overlapping checkpoints whose arrival order differs. No external factual claims were assumed beyond the draft; live browser gates remain required.
